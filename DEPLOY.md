# Развёртывание «Кто кому должен» — пошагово для Рашида

Ничего в терминале запускать не нужно, кроме одного места (шаг 9), и там написано,
что именно делает команда и как её без терминала обойти, если что-то пойдёт не так.
Всё остальное — клики в веб-кабинетах.

Итог должен получиться такой: сайт открывается по ссылке `https://ecochelovechik-cmyk.github.io/trip-split/`,
данные хранятся в облаке (Cloudflare), телеграм-бот отвечает на команды и раз в сутки
присылает сводку.

---

## Шаг 1. Регистрация в Cloudflare

1. Откройте **dash.cloudflare.com**.
2. Нажмите **Sign up**, введите почту (можно ту же, `ecochelovechik@gmail.com`) и пароль.
3. Подтвердите почту по ссылке из письма.
4. Как понять, что готово: вы видите главную панель Cloudflare (Dashboard) с пустым списком
   проектов слева.

Если что-то не пришло на почту — проверьте папку «Спам», письмо от `noreply@notify.cloudflare.com`.

---

## Шаг 2. Создание базы D1 и применение схемы

D1 — это база данных Cloudflare, в ней будет храниться журнал операций поездки.

1. В левом меню панели найдите **Storage & Databases → D1 SQL Database** (или просто **D1**
   в поиске по панели).
2. Нажмите **Create database**.
3. Имя базы: `trip-split-db` (можно другое, но дальше в инструкции используется это имя —
   если назовёте иначе, просто подставляйте своё имя везде, где встретите `trip-split-db`).
4. Нажмите **Create**.
5. Откроется страница базы. Найдите вкладку **Console** (консоль запросов) — там можно
   выполнять SQL прямо в браузере.
6. Откройте на компьютере файл `worker/schema.sql` (можно двойным кликом в Проводнике —
   откроется в Блокноте) и скопируйте оттуда весь текст.
7. Вставьте скопированный текст в поле консоли D1 в браузере и нажмите **Execute**
   (или **Run**).
8. Как понять, что получилось: в ответе консоль покажет что-то вроде «2 tables created»
   или список выполненных команд без ошибок красным цветом. Если хотите убедиться —
   выполните там же отдельным запросом `SELECT name FROM sqlite_master WHERE type='table';`
   — должны появиться строки `trips` и `ops`.

Если консоль ругается красным текстом — скорее всего скопировался не весь файл целиком
(в схеме два `CREATE TABLE` и один `CREATE INDEX` — все три должны быть в вставленном тексте).

---

## Шаг 3. Создание Worker и вставка кода

Worker — это серверная часть: она принимает запросы от сайта и от Telegram и обращается к базе.

1. В левом меню — **Compute (Workers) → Workers & Pages**.
2. **Create** → **Create Worker** (можно также «Start from Hello World»).
3. Имя воркера: `trip-split-api` (тоже можно своё — тогда адрес сервера будет отличаться,
   не забудьте подставить своё имя в дальнейших шагах).
4. Нажмите **Deploy** — Cloudflare создаст болванку и покажет адрес вида
   `https://trip-split-api.<ваш-логин>.workers.dev`. **Скопируйте и сохраните этот адрес** —
   он понадобится в шаге 7 и в конце.
5. Нажмите **Edit code** (или **Continue to project** → **Edit code**) — откроется
   встроенный редактор кода в браузере.
6. В файловом дереве редактора будет один файл — обычно `worker.js` или `index.js`.
   Выделите в нём **весь** текст (Ctrl+A) и вставьте вместо него содержимое файла
   `C:\Users\ecoch\Tools\trip-split\worker\bundle.js`.

   Это специально собранный «всё в одном» файл: серверная часть и телеграм-часть уже
   склеены, создавать второй файл в редакторе не нужно. Открыть его на компьютере:
   Проводник → путь выше → открыть Блокнотом → Ctrl+A → Ctrl+C.

   Если позже что-то менялось в коде — файл нужно пересобрать заново
   (в папке проекта командой `node dev/build-worker.mjs`), иначе вставится старая версия.

7. Пока не нажимайте «Deploy» окончательно — сначала настройте переменные и D1
   (следующие шаги), потом сохраните всё разом.

Как понять, что получилось: в редакторе один файл, он начинается со строки-комментария
«СОБРАННЫЙ ФАЙЛ — не редактировать вручную», ошибок (красных подчёркиваний по всему
файлу) нет.

## Шаг 4. Переменные окружения (секреты)

Здесь два секрета: токен бота и секретный кусок адреса вебхука. **Их нельзя никому
показывать и нельзя вставлять прямо в код** — только через это меню.

1. На странице воркера откройте вкладку **Settings → Variables and Secrets**
   (или **Settings → Environment Variables** в старом интерфейсе).
2. Добавьте переменную:
   - Имя: `BOT_TOKEN`
   - Значение: токен, который вы получите в шаге 10 у @BotFather (сейчас можно
     вписать любую заглушку, например `TEMP`, и вернуться сюда после шага 10 —
     обязательно исправить на настоящий).
   - Тип: **Secret** (не «Text») — так значение не будет видно потом даже вам,
     только воркеру.
3. Добавьте вторую переменную:
   - Имя: `TG_WEBHOOK_SECRET`
   - Значение: придумайте длинную случайную строку без пробелов, например
     `a8f3k29dmz71qlx0vt` (замените на свою — это часть адреса вебхука, чем
     случайнее, тем безопаснее). **Запишите её себе** — понадобится в шаге 9.
   - Тип: **Secret**.
4. Нажмите **Save** / **Deploy**.

Как понять, что получилось: в списке переменных видно `BOT_TOKEN` и `TG_WEBHOOK_SECRET`
со значением, скрытым звёздочками (`•••••`).

Необязательно: если вы захотите разместить сайт не на GitHub Pages, а на своём домене,
можно добавить ещё переменную `PAGES_URL` со своим адресом — без неё бот сам подставит
`https://ecochelovechik-cmyk.github.io/trip-split/`.

## Шаг 5. Привязка базы D1 к Worker

1. Там же, на странице воркера — вкладка **Settings → Bindings** (или **Variables →
   D1 Database Bindings** в старом интерфейсе).
2. **Add binding** → тип **D1 Database**.
3. Поле **Variable name** — впишите ровно `DB` (заглавными буквами, без вариантов —
   код воркера обращается именно к `env.DB`).
4. Поле **D1 database** — выберите `trip-split-db`, созданную в шаге 2.
5. **Save** / **Deploy**.

Как понять, что получилось: в списке привязок появилась строка `DB → trip-split-db`.

---

## Шаг 6. Cron-триггер (вечерняя сводка)

1. Вкладка **Settings → Trigger Events** (или **Triggers → Cron Triggers**).
2. **Add Cron Trigger**.
3. Введите расписание в формате cron. Например, чтобы сводка приходила в 20:00
   по Ташкенту (UTC+5) — это 16:00 UTC, cron-строка: `0 15 * * *`.
   Cloudflare всегда считает время по UTC, не по Ташкенту — если хотите другое
   время получения, отнимите 5 часов от нужного ташкентского времени.
4. **Save**.

Как понять, что получилось: в списке триггеров видна строка с вашим расписанием.
Само по себе расписание ничего не отправит, пока не привязан бот (шаги 4 и 10) —
это нормально на этом этапе.

---

## Шаг 7. Проверка, что сервер живой

1. Откройте в браузере адрес из шага 3 с добавлением `/api/health`, например:
   `https://trip-split-api.<ваш-логин>.workers.dev/api/health`
2. Должна открыться страница с текстом вроде `{"ok":true,"ts":1755900000000}`.

Если вместо этого ошибка `1101` или `1102` (Cloudflare показывает красную страницу) —
значит в коде опечатка при вставке в шаге 3, или не сохранены обе переменные из шага 4.
Откройте вкладку **Logs** на странице воркера — там будет текст ошибки.

## Шаг 8. Включение GitHub Pages

1. Откройте репозиторий на GitHub: `github.com/ecochelovechik-cmyk/trip-split`
   — он уже создан, код в нём лежит, файлы сайта в папке `docs`.
2. **Settings** (в самом репозитории, не в настройках аккаунта) → **Pages** в левом меню.
3. **Source** — выберите **Deploy from a branch**.
4. **Branch** — `main`, папка — **`/docs`** (именно docs, не root: в корне лежит
   серверный код и документация, сайт — только в `docs`).
5. **Save**.
6. Подождите 1–2 минуты, обновите страницу — появится зелёная плашка со ссылкой
   `https://ecochelovechik-cmyk.github.io/trip-split/`.

Если Pages уже включён (это могло быть сделано заранее) — шаг пропускается,
просто проверьте, что в **Settings → Pages** стоит ветка `main` и папка `/docs`.

Как понять, что получилось: ссылка открывается и показывает страницу приложения
(не ошибку 404).

## Шаг 9. Адрес сервера в конфиге сайта

1. Откройте файл `docs/config.js` в репозитории (на GitHub — кнопка с карандашом
   «Edit this file», либо у себя на компьютере в Блокноте, если правите локально).
2. Впишите туда адрес воркера из шага 3, например:
   ```js
   window.TRIP_API = "https://trip-split-api.<ваш-логин>.workers.dev";
   ```
   (без слэша на конце).
3. Сохраните — на GitHub кнопка **Commit changes**.

Единственное место, где в этой инструкции упоминается терминал: если вы правите файлы
не через веб-интерфейс GitHub, а через папку на компьютере, синхронизированную с
репозиторием — потребуется программа Git и команда вида `git add . && git commit -m "..."
&& git push`. Она забирает изменённые файлы с диска и отправляет их на GitHub.
Если это звучит непонятно — проще и безопаснее пользоваться кнопкой **Edit** прямо
на сайте GitHub, как в пункте 1–3 выше, без терминала вообще.

## Шаг 10. Создание бота у @BotFather

1. В Telegram найдите **@BotFather** (официальный, с синей галочкой).
2. Отправьте `/newbot`.
3. Введите имя бота (то, что будет показываться в чате) — например, «Кто кому должен».
4. Введите username бота — обязательно заканчивается на `bot`, например `kkd_trip_bot`
   (если занято — попробуйте другой вариант).
5. BotFather пришлёт токен — длинную строку из цифр, двоеточия и латинских букв —
   скопируйте его.
6. Вернитесь в Cloudflare (шаг 4) и замените заглушку в `BOT_TOKEN` на этот настоящий
   токен. **Save** / **Deploy**.
7. Опишите бота (необязательно, но приятно): отправьте BotFather `/setdescription`,
   выберите бота, напишите «Считаю, кто кому должен в общей поездке».
8. Кнопка меню на Mini App: отправьте BotFather `/newapp` (или `/mybots` → выберите
   бота → **Bot Settings → Menu Button → Configure menu button**), укажите:
   - URL: адрес из шага 8, `https://ecochelovechik-cmyk.github.io/trip-split/`
   - Название кнопки: «Открыть поездку»
9. Установка вебхука — откройте в браузере ссылку, подставив свой токен и свой
   секрет из шага 4 (это единственный способ без терминала — просто открыть ссылку):
   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/setWebhook?url=https://trip-split-api.<ваш-логин>.workers.dev/api/tg/webhook/<ВАШ_TG_WEBHOOK_SECRET>
   ```
   Подставьте вместо `<ВАШ_ТОКЕН>` токен из пункта 5, вместо
   `<ваш-логин>` — ваш логин Cloudflare из адреса воркера, вместо
   `<ВАШ_TG_WEBHOOK_SECRET>` — строку, которую вы придумали в шаге 4.
   В ответ должно прийти `{"ok":true,"result":true,"description":"Webhook was set"}`.

Как понять, что всё работает: напишите боту `/start` в Telegram — должно прийти
приветствие с кнопкой «Открыть поездку».

## Шаг 11. Привязка чата к поездке

1. Откройте сайт по ссылке из шага 8, создайте поездку (введите название, добавьте
   участников) — в адресной строке появится метка вида `#AbC123xyz` — это и есть id
   поездки, ссылка целиком — ключ доступа, отправьте её попутчикам.
2. В Telegram-группе поездки (или в личном чате с ботом) отправьте:
   `/privyazat https://ecochelovechik-cmyk.github.io/trip-split/#AbC123xyz`
   (можно и просто `/privyazat AbC123xyz` — бот сам вырежет id из ссылки).
3. Бот подтвердит: «Готово. Этот чат привязан к поездке «...»».
4. Проверка: напишите «итог» — бот должен ответить расчётом (если трат ещё нет —
   покажет пустой список участников без ошибок).

## Итоговая проверка всего целиком

- [ ] `/api/health` в браузере отдаёт `{"ok":true,...}` (шаг 7)
- [ ] Сайт открывается по ссылке GitHub Pages, не пустой (шаг 8)
- [ ] На сайте создалась поездка, добавление траты не выдаёт ошибок
- [ ] Бот отвечает на `/start` кнопкой «Открыть поездку»
- [ ] После `/privyazat` команда «итог» в чате показывает расчёт
- [ ] На телефоне сайт можно добавить на главный экран (иконка — тёмный квадрат
      со стрелками, не белый прямоугольник с текстом — если белый, значит
      `manifest.webmanifest` или иконки не подцепились, проверьте пути в шаге 9)

Если что-то не сходится — самый частый источник проблем: не то имя привязки D1
(должно быть ровно `DB`, шаг 5), не сохранённые секреты (шаг 4), или несовпадающий
`TG_WEBHOOK_SECRET` в переменной Cloudflare и в ссылке `setWebhook` (шаг 10, пункт 9) —
эти две строки должны быть одинаковыми посимвольно.
