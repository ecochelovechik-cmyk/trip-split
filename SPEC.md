# Дележка расходов в поездке — контракт проекта

Общий документ для всех, кто пишет части. **Отступать от него нельзя** — части собираются вместе.

## Что делаем

Приложение «кто кому должен» для компании в поездке: несколько человек с разных телефонов
вносят траты в одну общую базу, приложение считает, кто кому сколько отдаёт.

- Фронт — статика на GitHub Pages: `https://ecochelovechik-cmyk.github.io/trip-split/`
- Бэкенд — Cloudflare Worker + база D1
- Вход двумя путями: обычная ссылка в браузере и Telegram Mini App (тот же адрес)

## Ключевое архитектурное решение: журнал операций

Состояние поездки целиком **не пересылается и не перезаписывается**. Телефон отправляет
операции («добавил трату»), сервер присваивает каждой номер `seq`, остальные телефоны
докачивают только новые операции и складывают из них состояние.

Почему так: пять человек вносят траты одновременно, часто без связи. Перезапись всего
состояния теряет чужие записи; журнал — нет.

### Формат операции

```js
{
  id: "l3k2j-x8f2a",   // уникальный id операции, генерирует телефон (защита от дублей при досылке)
  kind: "expense.add", // см. список ниже
  ts: 1755900000000,   // unix ms, время на телефоне
  author: "Аня",       // имя автора; для Telegram сервер подставляет проверенное имя
  payload: { ... }     // поля зависят от kind
}
```

### Виды операций (kind) и payload

| kind | payload |
|---|---|
| `trip.meta` | `{name?, base?}` — название поездки, базовая валюта |
| `person.add` | `{pid, name}` |
| `person.rename` | `{pid, name}` |
| `person.del` | `{pid}` |
| `cur.set` | `{code, rate}` — курс: сколько базовой за 1 единицу `code` |
| `cur.del` | `{code}` |
| `expense.add` | `{eid, title, amount, cur, payer, parts:[pid], date:"YYYY-MM-DD", note}` |
| `expense.edit` | `{eid, ...те же поля}` — полная замена полей траты |
| `expense.del` | `{eid}` |
| `payment.add` | `{payid, from, to, amount, date, note}` — возврат долга, `amount` в базовой валюте |
| `payment.del` | `{payid}` |

### Свёртка операций в состояние (одинаково на клиенте и в боте)

Операции применяются строго по возрастанию `seq`. Правила:

- `person.del` / `expense.del` / `payment.del` — удаляют запись, если она есть; иначе игнор.
- `expense.edit` для несуществующей траты — игнор (её удалили).
- Повторное `person.add` с тем же `pid` — игнор.
- Конфликт правок одной траты — выигрывает операция с бо́льшим `seq`.

Итоговое состояние:

```js
{
  trip: {name, base},
  currencies: [{code, rate}],   // базовая валюта всегда rate = 1
  people:  [{id, name}],
  expenses:[{id, title, amount, cur, payer, parts:[], date, note}],
  payments:[{id, from, to, amount, date, note}]
}
```

## Деньги — правила, отступать нельзя

- Все внутренние расчёты — **в целых центах базовой валюты** (`Math.round(amount * rate * 100)`).
  Никаких промежуточных дробей: иначе копейки не сходятся.
- Доля участника: `per = Math.floor(cents / n)`, остаток `rem = cents - per*n` раздаётся
  по одной копейке первым `rem` участникам **в порядке списка людей** (детерминированно).
- Сумма долей обязана равняться сумме траты до копейки; сумма всех балансов — ноль.
- Баланс: `заплатил − своя доля + отданные возвраты − полученные возвраты`.
- Взаимозачёт: жадный алгоритм (крупнейший должник → крупнейшему кредитору), пока не сойдётся.
- Валюты без копеек (`UZS, JPY, KRW, VND, IDR, KZT, KGS, ...`) выводятся без дробной части,
  но внутри всё равно считаются в центах.

Эталон проверки (обязан сходиться): трата 10.00 на троих → доли 334, 333, 333 центов.

## API

База: `https://<worker>.workers.dev`. Все ответы — JSON, UTF-8.
CORS: `Access-Control-Allow-Origin: *`, методы `GET, POST, OPTIONS`, заголовок `content-type`.
Доступ к поездке = знание её `tripId` (ссылка и есть ключ, как решено для калькулятора).

| Метод | Путь | Тело / параметры | Ответ |
|---|---|---|---|
| POST | `/api/trip` | `{name, base}` | `{tripId}` |
| GET | `/api/trip/:id` | `?since=<seq>` | `{tripId, title, seq, ops:[{seq, id, kind, ts, author, payload}], more:bool}` |
| POST | `/api/trip/:id/ops` | `{ops:[...], author, initData?}` | `{seq, applied:[opId]}` |
| POST | `/api/tg/webhook/:secret` | апдейт Telegram | `{ok:true}` |
| GET | `/api/health` | — | `{ok:true, ts}` |

Правила:
- `POST /ops` идемпотентен по `op.id` (`INSERT OR IGNORE`) — досылка из офлайн-очереди безопасна.
- Если передан `initData` (Telegram) — сервер проверяет подпись HMAC-SHA256 по токену бота
  и **подставляет проверенное имя автора**, игнорируя присланное. Без подписи автор — как прислали.
- Лимиты: ≤ 50 операций в запросе, payload ≤ 4 КБ, ≤ 5000 операций на поездку,
  `GET` отдаёт ≤ 500 операций за раз (`more:true` — надо запросить ещё).
- Ошибки: `{error:"код", message:"по-русски"}` + HTTP-статус. Коды: `not_found`, `too_large`,
  `too_many`, `bad_request`, `rate_limited`.

## Схема базы

См. `worker/schema.sql` — таблицы `trips` и `ops`, `seq INTEGER PRIMARY KEY AUTOINCREMENT`,
`op_id TEXT UNIQUE` (идемпотентность), индекс `ops(trip_id, seq)`.

## Клиент: хранение и синхронизация

- `localStorage`:
  - `ts.trips` — список поездок `[{id, name, base, lastSeq, state}]` (свёрнутое состояние + номер)
  - `ts.queue.<tripId>` — неотправленные операции (офлайн-очередь)
  - `ts.me.<tripId>` — кто я в этой поездке (только на этом телефоне)
  - `ts.lang` — язык интерфейса
- Опрос сервера: сразу после своей операции, при возврате фокуса на вкладку, и раз в 8 секунд,
  пока экран активен. Никаких сокетов.
- Нет связи: операция применяется локально, ложится в очередь, экран показывает «не отправлено N».
  При восстановлении — досылка, затем обычный опрос.
- Адрес сервера берётся из `docs/config.js` (`window.TRIP_API`). Если пусто или сервер
  недоступен — приложение работает как одиночное, с честным баннером «общая база недоступна».

## Telegram

- Mini App открывает тот же адрес Pages. Если есть `window.Telegram.WebApp` — вызвать `ready()`,
  `expand()`, взять имя из `initDataUnsafe.user`, отправлять `initData` вместе с операциями.
- Бот: кнопка «Открыть поездку», команда «итог» (`/itog`) — печатает, кто кому должен,
  вечерняя сводка раз в день (Cron Trigger). На каждую трату бот не пишет.
- Токен бота — только в переменных окружения Cloudflare (`BOT_TOKEN`), **в файлы не класть**.

## Мобильные грабли (проверены на живом iPhone, повторить нельзя)

1. Без `<meta name="viewport">` телефон рисует страницу шириной 980px и сжимает.
2. Самодельные кнопки-переключатели на iOS не срабатывают — только родные
   `<input type="radio">` + `<label for>`; JS лишь читает результат.
3. Авторское `label{display:flex}` перебивает атрибут `hidden` → нужно
   `[hidden]{display:none !important;}`.
4. У `<ul>` остаётся браузерный отступ 40px — сбрасывать.
5. **При каждом обновлении менять версию кэша в `sw.js`**, иначе у людей останется старая копия.
6. В подвале — строка «Версия от ДД.ММ.ГГГГ», чтобы было видно, свежую ли копию открыл человек.
7. Тап-таргеты не меньше 44px по высоте на телефоне.

## Что нельзя делать (уроки прошлых потерь данных)

- Никакого «умного» слияния записей по совпадению названия. Добавление — всегда добавление,
  обновление — только по явному «открыть и изменить».
- Ошибки записи показывать человеку, не глотать `try/catch` молча.
- Не хранить секреты в файлах репозитория.
